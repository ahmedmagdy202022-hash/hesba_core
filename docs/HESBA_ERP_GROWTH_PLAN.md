## 1. حِسبة فين دلوقتي (بناءً على الكود، مش على الذاكرة)

**موجود وشغال:**
- **البيع:** فواتير ومرتجعات بيع، كاشير بيشتغل أونلاين وأوفلاين، تقسيط، قوائم أسعار، ضريبة قيمة مضافة، الفاتورة الإلكترونية (ETA v1.0)، طباعة A4 و80 مم.
- **الشراء:** فواتير ومرتجعات شراء، سداد للموردين.
- **المخزون:** أكتر من مخزن، تحويل بين المخازن، جرد، تسويات، حد الطلب، وحدات، تشغيلات وصلاحية، مقاسات وألوان، سيريال وضمان، باركود (مسح بالكاميرا، تصميم ملصقات، PDF).
- **الفلوس:** خزن، مصروفات، كشف حساب للعميل والمورد، أعمار الديون، إقفال الفترات، الأصول الثابتة والإهلاك، الورديات.
- **الأنشطة:** مطاعم (طاولات)، مواعيد وزيارات، موظفين وفنيين بعمولة، مشاريع ومقاولات، تصنيع (وصفات وتشغيلات).
- **المنصة:** صلاحيات وأدوار، سجل مراجعة (audit)، استيراد من برامج قديمة، نسخ احتياطي مشفّر، إيميل متابعة يومي، عربي وإنجليزي، ويب وتابلت وموبايل.

**الفجوات الكبيرة:**

| # | الفجوة | ليه مهمة |
|---|---|---|
| G1 | **مفيش دفتر أستاذ عام** (دليل حسابات وقيود يومية) | من غيره مفيش قوائم مالية حقيقية: لا ميزانية، ولا قائمة دخل كاملة، ولا تدفقات نقدية، ولا ميزان مراجعة. |
| G2 | **مفيش فروع / كيانات** | مصنع ومحلات كل واحد بحساباته مش ممكن، ومفيش تبويب لكل كيان ولا تقرير مجمّع. |
| G3 | **الشركة ليها نشاط واحد** | المصنع والمحل تحت نفس الشركة مينفعش يبقى لكل واحد نشاطه. |
| G4 | **المصطلحات والداشبورد واحدة لكل الأنشطة** | العيادة بتقول «مريض» والمصنع بيقول «خامة»، والبرنامج بيقول «عميل» و«صنف» لكل الناس. |
| G5 | **مفيش تقارير أداء للموظفين** | ربحية كل بياع، إنتاجيته، وتنبيه لما أداؤه يقل مع السبب. |
| G6 | **دورات العمليات ناقصة خطوات** | عرض سعر ← أمر بيع ← تسليم ← فاتورة. طلب شراء ← أمر شراء ← استلام. وموافقات على الخصم والشراء. |
| G7 | **التصنيع بيتسجل كتسويات مخزون** (HG-030) | مفيش تكلفة تصنيع حقيقية: إنتاج تحت التشغيل، عمالة ومصاريف، هالك، فرق تكلفة. |
| G8 | **مفيش موارد بشرية ومرتبات** | حضور وانصراف، إجازات، مرتبات وتأمينات (مصر). |
| G9 | **مفيش CRM** | فرص بيع، متابعة عملاء محتملين. |
| G10 | **مفيش عملات متعددة، ولا تسوية بنكية، ولا موازنات** | |
| G11 | **مفيش شركات قانونية منفصلة تحت نفس الحساب** | multi-company زي Odoo. |

## 2. هدف واقعي

Odoo معمول على مدار سنين طويلة ووراه فرق كبيرة. نسخه بالكامل مش هدف عملي.

**الهدف:** نبقى بقوة Odoo في القلب اللي الشركات الصغيرة والمتوسطة في مصر بتستخدمه فعلاً، وهو: **المحاسبة، والبيع، والشراء، والمخزون، والتصنيع، والفروع، والأداء، والمرتبات**. ونتميّز عليه في:
- العربي المصري والبساطة.
- الكاشير اللي بيشتغل من غير نت.
- الفاتورة الإلكترونية.
- السعر.
- إن البرنامج يتكيّف مع كل نشاط.

## 3. المبادئ (عشان القوة متجيش على حساب الصحة)

1. **دفتر الأستاذ بيتبني من المستندات اللي اتسجلت قبل كده.** في الأول هيبقى نسخة مشتقة تقدر تتبني من جديد في أي وقت، ومن غير ما نغيّر منطق الترحيل المحمي. ومينفعش يبقى هو المصدر الأساسي غير لما اختبارات المطابقة تثبت إن أرصدته = تقارير العملاء والموردين والخزن والمخزون بالقرش.
2. **الفرع بُعد في كل حاجة من أول يوم:** في القيود والمستندات والصلاحيات. لو اتضاف بعدين معناه نعيد بناء كل حاجة.
3. **أي تعديل محمي يتسجل Hard Gate:** السبب، والملفات، والخطر، والاختبارات، وبعدين التنفيذ بموافقتك.
4. **كل task:** branch من `develop`، اختبارات على SQLite وPostgreSQL، وPR لوحده.

### المرحلة 0: البرنامج يتكيّف مع النشاط (طريقة العرض بس، ملهاش خطورة) · 2 PR
- **ACT-PROFILE-001: ملف النشاط.**
  - قاموس مصطلحات لكل نشاط ونشاط فرعي، زي: عميل ← مريض / طالب / نزيل، صنف ← خدمة / وجبة / خامة / منتج تام، فاتورة ← كشف / أمر شغل / طلب.
  - بيتطبّق على القوائم والعناوين والأزرار من خلال template tag واحد.
  - **القبول:** نفس الشاشة تطلع بمصطلحات مختلفة لعيادة ولمحل، والاختبار بيغطي كل الأنشطة.
- **ACT-PROFILE-002: داشبورد وقائمة لكل نشاط.**
  - مجموعة مؤشرات وترتيب للقائمة وأزرار سريعة لكل نشاط:
    - **مطعم:** طاولات مفتوحة، متوسط الطلب، الذروة.
    - **مصنع:** إنتاج النهارده، خامات قربت تخلص، تكلفة الوحدة.
    - **عيادة / خدمات:** مواعيد النهارده، اللي ماجوش، دخل كل خدمة.
    - **مقاولات:** المشاريع، والمصروف مقابل الميزانية.
  - في الديمو: زرار تبدّل منه النشاط.

### المرحلة 1: المحاسبة والقوائم المالية (G1 + G10) · 7–8 PR
- **GL-000: تصميم مكتوب** (HG): دليل الحسابات، وربط كل نوع مستند بقيده، وبُعد الفرع، وطريقة المطابقة. **ده أول حاجة، ومحتاج موافقتك.**
- **GL-001: دليل حسابات** مصري افتراضي لكل نشاط: أصول، خصوم، حقوق ملكية، إيرادات، مصروفات، تكلفة. قابل للتعديل، بأكواد هرمية.
- **GL-002: محرّك القيود (projection).**
  - كل مستند متسجل يتحوّل لقيد مزدوج: بيع، مرتجع، شراء، سداد، تحصيل، حركة خزنة، مصروف، تسوية مخزون، إهلاك، تقسيط.
  - أمر يعيد بناء القيود، واختبارات مطابقة: رصيد حساب العملاء = تقرير العملاء، وكذلك الموردين والخزن وقيمة المخزون.
- **GL-003: قيود يدوية** للمحاسب، وقيد افتتاحي، وقيود تسوية آخر الفترة، مع مراجعة واعتماد وعكس للقيد بدل المسح.
- **FS-001: القوائم المالية:** ميزان مراجعة، قائمة الدخل، الميزانية العمومية، التدفقات النقدية (غير مباشرة). مقارنة بفترة قبلها، والتصدير PDF وExcel، والتقرير لفرع واحد أو مجمّع.
- **FS-002: دفتر أستاذ لكل حساب** مع النزول للمستند الأصلي. وتحليل مالي: نسب السيولة والربحية، ورأس المال العامل.
- **BANK-001: حسابات بنكية** (نوع خزنة)، واستيراد كشف بنك، وتسوية بنكية.
- **BUD-001: موازنات** مقابل الفعلي لكل حساب وفرع. **MCUR-001: عملات متعددة** وفروق عملة. (ممكن تتأجل)

### المرحلة 2: الفروع والكيانات (G2 + G3) · 5 PR
- **BR-000: تصميم مكتوب** (⚠️ HG): نموذج الفرع وعلاقته بالمخازن والخزن والمستخدمين والمستندات، وهل الفرع كيان قانوني ولا تشغيلي بس.
- **BR-001: الفرع ⚠️**
  - كل مخزن وخزنة ومستند بيتبع فرع.
  - البيانات الموجودة تروح لـ«الفرع الرئيسي» تلقائياً، فمفيش أي حاجة شغالة هتبوظ.
- **BR-002: صلاحيات حسب الفرع ⚠️**
  - الموظف يشوف ويسجّل في فرعه بس.
  - المالك والمدير العام بيشوفوا كل الفروع.
- **BR-003: تبويب لكل كيان.**
  - شريط فوق: «الشركة كلها | المصنع | محل 1 | محل 2».
  - كل تبويب ليه داشبورد وتقارير وقوائم مالية لوحده، و«الشركة كلها» بيجمّع.
- **BR-004: نشاط لكل فرع.** المصنع بمصطلحات وداشبورد التصنيع، والمحل بتاعة التجارة. بيتبني على ACT-PROFILE.
- **BR-005: التوريد بين الفروع ⚠️**
  - تحويل داخلي بالتكلفة، أو فاتورة داخلية بسعر تحويل (لو الكيانات منفصلة).
  - استبعاد الحركات الداخلية في التقرير المجمّع.

### المرحلة 3: الأداء والتنبيهات الذكية (G5) · 4 PR
- **PERF-001: البياع المسؤول عن الفاتورة ⚠️ (صغيرة)**
  - حقل «البياع» على فاتورة البيع، افتراضياً اللي سجّلها، ويتغيّر.
  - في الكاشير هو الكاشير.
- **PERF-002: بطاقة أداء لكل موظف:**
  - المبيعات، ومجمل الربح، والهامش، وعدد الفواتير، ومتوسط الفاتورة.
  - نسبة الخصم، ونسبة المرتجع، ونسبة تحصيل آجله، والعمولة.
  - المقارنة: بمتوسط الفريق، وبنفسه في آخر 3 شهور.
- **PERF-003: تحذير «أداء متأثر» بسبب مكتوب.** مثال: «مبيعات أحمد قلّت 35% عن متوسطه. السبب: الفواتير قلّت من 40 لـ 22، ومتوسط الفاتورة ثابت. يعني المشكلة في عدد الزباين مش في السعر.» القواعد:
  - انخفاض عن متوسطه أو عن الفريق بنسبة تحددها انت.
  - خصم أعلى من المعتاد.
  - مرتجعات كتير.
  - آجل مش بيتحصّل.
- **PERF-004: مؤشرات أداء حسب النشاط:**
  - **مطعم:** مبيعات كل ويتر، والطاولات اللي خدمها.
  - **خدمات:** شغلانات كل فني، وعمولته، والشغل اللي رجع تاني.
  - **تصنيع:** إنتاج كل تشغيلة، والهالك، وفرق التكلفة.
  - **مقاولات:** هامش كل مشروع، وانحرافه عن الميزانية.
- **ALERT-001: مركز تنبيهات بقواعد** بيغذّي الجرس والإيميل اليومي، وكل قاعدة بتتفعّل أو بتتقفل.

### المرحلة 4: دورات العمليات الكاملة (G6 + G7 + G8 + G9) · ~10 PR
- **SO-001:** عرض سعر ← أمر بيع ← تسليم جزئي ← فاتورة.
- **PO-001:** طلب شراء ← أمر شراء ← استلام جزئي ← فاتورة مورد.
- **APPROVE-001:** موافقات على خصم فوق حد معيّن، وتعدّي حد الائتمان، والمشتريات فوق مبلغ معيّن.
- **MFG-002 ⚠️ (يحل HG-030):** تكلفة تصنيع حقيقية: إنتاج تحت التشغيل، عمالة ومصاريف، هالك، وتكلفة فعلية مقابل معيارية.
- **LAND-001:** تكاليف الاستيراد على الشحنة (landed cost).
- **HR-001:** حضور وانصراف وإجازات. **PAY-001:** مرتبات مصرية (تأمينات وضرايب كسب عمل)، بقيود في الأستاذ.
- **CRM-001:** فرص بيع بسيطة: عميل محتمل ← عرض سعر ← بيع، ومتابعات.

### المرحلة 5: المنصة · حسب الطلب
- **MCO-001:** شركات قانونية منفصلة تحت اشتراك واحد، وتقارير مجمّعة.
- **API-001:** API وwebhooks للربط مع متجر أونلاين ومحاسب خارجي.
- **ETA-002:** الإيصال الإلكتروني (B2C).
- **XLS-001:** تصدير Excel من كل تقرير. **RPT-001:** منشئ تقارير بسيط.
- **SHOP-001:** طلبات عن طريق واتساب أو متجر بسيط.

## 5. الترتيب المقترح وليه

1. **ACT-PROFILE (مرحلة 0):** أسرع تأثير يبان في الديمو، ومفيهوش خطورة.
2. **GL-000 + BR-000 مع بعض كتصميم واحد:** لأن الفرع لازم يبقى بُعد في كل قيد من أول يوم.
3. **GL-001 ← GL-002 ← FS-001:** القوائم المالية قيمتها أعلى قيمة في البيع للعملاء، وأي تقرير جاي محتاجها.
4. **BR-001 ← BR-003:** تبويب لكل كيان.
5. **PERF-001 ← PERF-003:** أداء الموظفين وتنبيهاته.
6. باقي المرحلتين 4 و5 حسب طلب العملاء.

## 6. المخاطر

| الخطر | التقليل |
|---|---|
| غلط في القيود بيبوّظ ثقة المحاسب | الأستاذ مشتق ويتعاد بناؤه، ومطابقته بالقرش مع التقارير الحالية قبل ما يبقى المصدر الأساسي. |
| الفروع بتلمس كل حاجة | تصميم وموافقة الأول، و«فرع رئيسي» افتراضي للبيانات الموجودة، واختبارات صلاحيات لكل فرع. |
| التوسع بلا نهاية (scope creep) | كل مرحلة ليها شروط قبول، ومفيش مرحلة بتبدأ قبل ما اللي قبلها تخلص. |
| الأداء على قاعدة بيانات مجانية | indexes على الفرع والتاريخ، وملخصات شهرية جاهزة لما البيانات تكبر. |
