# 049 Foundation Models: Settings, Roles, Permissions

Checkpoint: `049_FOUNDATION_MODELS_SETTINGS_ROLES_PERMISSIONS`

## Scope

This step adds the first real foundation models for Hesba Core before building purchases, sales, inventory movements, or reports.

Added areas:

- Client installation settings inside the client's own database
- Feature flags and system settings
- Temporary support access grants
- Roles and atomic permissions
- User profile linked to a role
- Audit log foundation
- Initial role/permission seed data

## Client data ownership rule

Every client must have a separate database.

The client owns:

- Database account
- Production database ownership
- Backups
- Operational business data

Ahmed owns:

- Hesba system structure
- Core logic
- Setup process
- Updates
- Support process

Ahmed must not be the owner or superuser of a client production database.
Support access must be temporary, limited, reasoned, and auditable.

## Business rules protected by this step

This foundation step does not implement transaction logic yet, but it protects the direction of the next steps:

1. Sales do not create supplier dues.
2. Purchases do not create customer dues.
3. Cashboxes are affected only by actual paid amounts.
4. Inventory is affected by inventory movements only.
5. Reports are read-only permissions.
6. Profit and cost are sensitive permissions.
7. Permission changes and support access must be auditable.
8. Closed-period reopening is sensitive and owner-only by default.

## Default roles

### Owner

Sees and manages everything.

### Manager

Handles daily operations: sales, purchases, inventory, customers, suppliers, and most non-sensitive reports.

Does not get owner-sensitive permissions by default.

### Cashier

Handles sales and customer receipts only.

No cost, profit, supplier finance, cashbox finance, closing, imports, exports, or permission management.

### Stock Keeper

Handles items, purchases, stock viewing, transfers, and adjustments.

No profit access and no cashbox finance access.

### Accountant

Handles supplier payments, customer payments, cashbox movements, and financial reports.

Profit access is not granted by default and can be enabled deliberately later if the owner wants.

### Support

Very limited default access.

Real support access must be granted through `SupportAccessGrant` and logged in `AuditLog`.

## Notes for next steps

Next model steps should continue in this order:

1. Master data: locations, categories, items, customers, suppliers, cashboxes.
2. Purchases: purchase invoice header and lines.
3. Inventory movements generated by purchases.
4. Sales: sales invoice header and lines.
5. Inventory movements generated by sales.
6. Customer payments, supplier payments, and cashbox movements.
7. Read-only report views.

Do not jump to UI or dashboards before the data structure and transaction rules are stable.
