# قاعدة بيانات العميل على Supabase (DEPLOY-001)

الهدف: **العميل هو مالك قاعدة البيانات**، وحسبة بتتصل بيها بحساب محدود مش حساب المالك.
العميل يقدر في أي لحظة يوقف دخول حسبة، والداتا تفضل عنده كاملة.

> المبدأ مكتوب في `docs/client_ownership.md`: العميل يملك الداتا والنسخ الاحتياطية،
> وأحمد يملك البرنامج والتحديثات، وأحمد مش مالك قاعدة بيانات العميل.

## اللي بيعمله العميل (5 دقايق، مرة واحدة)

1. يدخل على <https://supabase.com> ويعمل حساب **بإيميله هو** (مش إيميل أحمد).
2. **New project**: يكتب اسم المحل، ويختار باسورد قوي للقاعدة (ده باسورد **المالك**، يحتفظ بيه لنفسه ومحدش ياخده)، ويختار أقرب منطقة (مثلاً Frankfurt).
3. من **SQL Editor** يلصق الكود اللي تحت ويغيّر `كلمة_سر_قوية` لباسورد جديد مختلف، ويدوس **Run**:

```sql
-- حساب خاص بحسبة: مش المالك، وله مساحة (schema) لوحده.
create role hesba_app with login password 'كلمة_سر_قوية';
create schema if not exists hesba authorization hesba_app;
alter role hesba_app set search_path = hesba;
```

4. من زرار **Connect** ← **Session pooler** ينسخ رابط الاتصال، ويغيّر فيه:
   - اسم المستخدم من `postgres.xxxx` لـ `hesba_app.xxxx` (نفس الحروف بعد النقطة)
   - الباسورد لباسورد `hesba_app` اللي كتبه في الخطوة 3

   الرابط بيبقى شكله كده:
   ```
   postgresql://hesba_app.xxxx:الباسورد@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
   ```
5. يحط الرابط ده في إعدادات تشغيل البرنامج (متغير `DATABASE_URL`) — ده الشيء الوحيد اللي البرنامج محتاجه.

### ليه Session pooler بالذات؟
- الاتصال المباشر في Supabase شغال على IPv6 بس، ومعظم أماكن تشغيل البرامج (زي Render) IPv4.
- الـ Session pooler (بورت 5432) شغال على IPv4 وبيدعم كل اللي Django محتاجه.
- **متستخدمش** Transaction pooler (بورت 6543) مع حسبة.

## العميل متحكم دايمًا

| عايز يعمل إيه | يكتب في SQL Editor |
|---|---|
| يوقف دخول حسبة فورًا (الداتا تفضل موجودة) | `alter role hesba_app nologin;` |
| يرجّع الدخول | `alter role hesba_app login;` |
| يغيّر باسورد حسبة | `alter role hesba_app password 'باسورد_جديد';` |
| يقرا الداتا بنفسه من حساب المالك | `grant hesba_app to postgres;` |

## حدود الخطة المجانية (اتراجعت سبتمبر 2026 — تتغير، راجعها وقت التسجيل)
- مساحة القاعدة: **500 ميجا** — تنبيه المساحة في حسبة بيقول قبل ما تقرب منها.
- المشروع **بينام لو مفيش ولا استخدام أسبوع كامل**، وبيصحى في حوالي 30 ثانية. محل شغال كل يوم مش هيتأثر، والنسخة الاحتياطية اليومية بتلمسه كل ليلة.
- **مفيش نسخ احتياطي أوتوماتيك في الخطة المجانية** — عشان كده حسبة بتعمل نسختها بنفسها، مشفّرة بمفتاح العميل (BACKUP-002).

## تشغيل البرنامج (متغيرات البيئة)

| المتغير | القيمة |
|---|---|
| `DATABASE_URL` | رابط الـ Session pooler بحساب `hesba_app` |
| `SECRET_KEY` | نص عشوائي طويل خاص بالعميل ده |
| `DEBUG` | `False` |
| `ALLOWED_HOSTS` | اسم الموقع، مثلاً `shop-name.onrender.com` |

وبعد أول تشغيل:
```
python manage.py migrate
python manage.py bootstrap_client --display-name "اسم المحل" --username owner
```

## ملاحظات أمان
- حسبة بتتصل بـ TLS دايمًا (`sslmode=require`) لأي قاعدة مش على نفس الجهاز.
- باسورد المالك (`postgres`) عمره ما بيتحط في حسبة ولا بيتبعت لحد.
- الجداول كلها جوه schema اسمها `hesba`، بعيد عن جداول Supabase نفسها.
